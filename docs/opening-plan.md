# 今後6か月の開封予定

「通院・目安」画面に表示する。認証・実績登録は変更しない。予備日数はEye Dropsのプロフィール設定としてクラウド保存する。予測は現在のStateから都度計算し、クラウドにも端末にも実績として保存しない。実績登録、訂正、在庫の変更、クラウド再取得後に新しいStateで再計算する。

## 予測

既存estimateDurationの有効履歴選別を利用し、一覧と処方相談ではall-averageを指定する。使い切り実績を優先し、ない場合は開封間隔を使う。ドルモロールは朝夜を分けず2本前との間隔、エイベリスは1本前との間隔。現在の設定版・並行本数と異なる履歴や取消・無効期間は既存ルールで除外。直近件数の制限を設けず、採用可能な履歴全件の単純平均（合計日数÷件数）を整数日に四捨五入する。使い切り実績と開封間隔を混ぜて二重に数えず、従来の使い切り優先は維持する。

既存openingScheduleの匿名枠シミュレーションで今日から6暦月後の前日までを列挙。使用中ボトルの残期間・個別期限と新規ボトルの設定期限を考慮。期限超過や使用中枠の不足は今日に繰り上げ、警告を表示。同薬剤・同日分を本数にまとめ、薬剤をまたいで日付順に並べる。現在の未開封在庫で対応できる本数と追加需要を分ける。今後の処方は未受取なので加算しない。

ホームの既存予測アルゴリズムは変更せず、この一覧と処方相談で全体平均の方式を採用する。異なる算出方式で日付が異なる場合がある。

## 処方相談

次回診察日は保存済み予定（過去なら今日）を初期値とし、次々回は3暦月後、予備日数は14日を提案。診察日は試算欄で変更しても保存せず、予備日数は「共通の予備日数を保存」でアカウント設定として確定する。予備は0〜90日。対象は次回診察日以上・次々回診察日＋予備日数未満。次回当日の開封を含め、予備0日の場合は次々回当日を含めない。

受診時未開封在庫＝max(0, 現在の未開封在庫−次回診察より前の開封需要)。希望本数＝max(0, 対象期間の必要本数−受診時未開封在庫)。受診前の不足は別に警告し、希望本数で過去の不足を補えるとは表示しない。多めの目安は採用期間の最短日数と受診時使用中残量0を使う既存の考え方を再利用。

## 予備日数の端末間共有

初期値は`lib/preferences.ts`のDEFAULT_RESERVE_DAYS（14日）。保存後は`eye_stock.profiles.reserve_days`が正。snapshotのreserveDaysを読み込み、Mac・iPhoneで同じアカウントの値を使う。未保存入力は試算として表示し、「共通の予備日数を保存」で確定。保存後のサーバー再取得を待って保存済み表示を更新する。

既存eye_stock_mutateにpreferences操作を追加し、プロフィール行ロック・revision・操作ID・監査ログ・結果不明時の確認を共用。古い端末からの上書きはPT409で拒否する。0日も保存可能。別端末への反映は従来どおり画面復帰時または明示更新。Realtimeや定期ポーリングは追加しない。未ログインのローカル試作はクラウド同期対象ではない。

DB変更は`supabase/sql/eye_stock_reserve_days.sql`（マイグレーション名eye_stock_account_reserve_days）。Eyeプロフィールの列・CHECK・その列のUPDATE権限、既存snapshot/mutateの関数本体だけを拡張。RLS・公開RPC署名・共有Auth・Lens Stockは変更なし。既存アカウントには14日を初期設定。
