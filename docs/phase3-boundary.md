# 本番適用前の境界

フェーズ2アプリはメモリ内の状態遷移とUIだけ。フェーズ3準備として未適用SQL候補を追加したが、接続設定や本番へのアクセスは含めない。

後続の専用RPCは eye_stock_*、非公開スキーマは eye_stock。
全テーブルRLS、Eye専用Auth UUIDと許可リスト、複合所有者FK、最小権限の専用実行ロール、空のsearch_pathを設計する。
業務上の競合に40001/40P01を使わない。PT409の現行PostgREST互換性を本番外で確認する。
更新はプロフィール行ロック・revision・操作ID照合・非負検査・増減履歴の一括トランザクション。
純粋関数の成功を実DBのRLS・トランザクションの検証と混同しない。

読取りはログイン時・更新後・必要な画面復帰時・明示更新で行い、重複取得はまとめる。定期ポーリングは行わない。
更新は自動再試行しない。結果不明操作を他操作より先に解決し、同じIDで照会・再試行する。
現在の同期アダプターは未接続。メールOTPとパスキーも未実装。

本番SQL適用、共有Auth設定変更、GitHubへの作成・公開、Vercel設定・公開は個別承認が必要。
Lens StockとBOXの既存オブジェクト・ACL・ユーザーは変更しない。
